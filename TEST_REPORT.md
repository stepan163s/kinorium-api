# Проверка Kinorium 0.1.1

Проверено 21 октября 2026 года на Python 3.9/macOS.
Отчёт не содержит данных для входа, cookies, идентификаторов тестового аккаунта
или персональных путей к файлам.

## Автоматические проверки

```sh
python3 -m unittest discover -s tests -v
```

**70 тестов проходят.** Проверки работают с локальными HTTP-серверами и имитацией ответов; внешний
аккаунт не используется. Покрыты:

- Подпись GET/POST/DELETE и сохранение точной кодировки URL.
- Передача формы, Unicode, спецсимволов, None и коллекций.
- Авторизация, повторный вход, отсутствие новой auth cookie, обновление cookies.
- HTTP 400/401/403/404/405/429/500, сетевые ошибки, пустой 204 и некорректный JSON.
- Сопоставление полей реальных ответов с моделями, вложенные модели и списки.
- Метаданные пакета, зависимости обоих клиентов, CLI и состав дистрибутива.
- Загрузка локальной конфигурации, приоритет окружения, скрытый ввод пароля.
- Исключение локальных секретов и отчётов из исходного дистрибутива.

## Проверка настоящего API

Углублённый прогон до подготовки релиза: **114 успешных проверок**, по 57
для синхронного и асинхронного клиентов. Проверены все публичные методы
обоих клиентов, cookie properties и активные методы моделей.

| Сценарий | Результат для обоих клиентов |
| --- | --- |
| Вход, собственный профиль, явный user_id | Успешно |
| Фильм и преобразование User/Movie/UserList | Успешно |
| Все списки аккаунта через клиент и модели | Успешно |
| Установка future/done/never и удаление каждого статуса | Подтверждено повторным чтением |
| Переходы future → done → never → future | Подтверждено повторным чтением |
| Установка оценки 1 и изменение на 10 | Подтверждено повторным чтением |
| Удаление оценки с сохранением done, повторное удаление | Подтверждено повторным чтением |
| POST и совместимый DELETE через data и params | Реальные изменения и удаления |
| Повторное удаление отсутствующей отметки | Успешно |
| Две непустые страницы, perpage=1 | Разные фильмы, модели корректны |
| Обычный HTTP DELETE без преобразования | NetworkError с HTTP 405 |
| Итоговые поля фильма, счётчики и содержимое списков | Совпали с исходными |

Отдельно проверены get_session.py, CLI, повторный вход со старой сессией,
закрытие и повторное открытие асинхронной сессии.

Для повторения на собственном тестовом аккаунте:

```sh
python3 tests/live_api_audit.py --credentials-file get_session.local.json \
  --allow-write --movie-id YOUR_BLANK_MOVIE_ID --report /tmp/kinorium-live-audit.json
```

Без --allow-write выполняется только чтение. Перед записью нужен фильм без
существующей отметки и заметки. Сценарий сохраняет исходные проверяемые поля
и результаты без пароля/cookies, выполняет очистку при исключении и сверяет
восстановление состояния после изменений.

## Найденные ограничения

- Сервер отклоняет now с кодом 403. Поддерживаются проверенные done/future/never.
- Удаление отметки реализовано сервером через POST removeMovieStatus с type=status;
  HTTP DELETE для этого endpoint не поддерживается.
- request() позволяет вызвать произвольный серверный метод. Неизвестные методы
  сервера и все возможные комбинации параметров не проверялись.
- WebSocket-клиента нет: проверена только функция подписи по известному вектору.
- Серверная история действий отдельно не сверялась. Временные оценки и отметки
  удалены, проверенные поля и списки восстановлены.

## Проверка установки

Исправление упаковки проверено с системным Python Apple/pip 21.2.4,
современным pip и чистым виртуальным окружением. Метаданные из setup.cfg
читаются и старым setuptools; пакет содержит оба клиента и их зависимости.
Релизные wheel и sdist дополнительно проверяются на состав и отсутствие
локальных конфигураций перед публикацией.

## Проверка публикуемых данных

- Данные для входа вынесены из отслеживаемого исходного файла в локальный JSON,
  исключённый из Git и исходного дистрибутива.
- Проверены точные значения локальных credentials и их распространённые
  кодировки в подготовленном содержимом Git; совпадений нет.
- История Git и публикуемые исходники проверены Gitleaks 8.30.1. Единственные
  исходные срабатывания — четыре известные тестовые подписи. Исключения
  ограничены точными значениями, одним тестовым файлом и соответствующим правилом.
- Публикуемый отчёт не содержит идентификаторов тестового аккаунта и личных путей.
- Для новых коммитов и тега используется адрес GitHub noreply.
